# Database

Every store in the runtime (sessions, messages, memories, scheduler, identity, rate limits...) talks to the database through the storage SDK ([`packages/storage`](../packages/storage)). Which database sits behind it is configuration:

| `DATABASE_PROVIDER` | Database | Use it for |
|---|---|---|
| `cosmosdb` (default) | Azure Cosmos DB for NoSQL, serverless or provisioned | Azure deployments; what the Pulumi program creates |
| `postgres` | PostgreSQL 13+ with pgvector | Any Postgres you run or rent; the easiest local setup |
| `memory` | In-process, lost on exit | Tests and single-process experiments |
| a package name or path | Your own adapter | Anything else ([writing an adapter](../packages/storage/README.md#writing-an-adapter)) |

Both real adapters pass the same conformance suite, so the runtime behaves the same on either: the same conflicts, etag checks, TTLs, query results and search ranking rules. The documented differences are listed under [What differs](#what-differs).

## Cosmos DB

The default, and what `pulumi up` creates: the account, the database and every container, with the runtime's managed identity granted data access (no keys).

| Setting | Env var | Default |
|---|---|---|
| `database.endpoint` | `COSMOS_ENDPOINT` | required |
| `database.key` | `COSMOS_KEY` | empty: Entra ID (managed identity on Azure, `az login` locally) |
| `database.databaseId` | `COSMOS_DATABASE` | `agentforeach` |
| | `COSMOS_IDENTITY_CLIENT_ID` | system-assigned identity |
| | `DATABASE_PROVISION` | `false` on Azure Functions (containers come from the IaC), `true` anywhere else |

Containers are defined in code. `npm run db:catalog --workspace @agentforeach/gateway` writes them to [`infra/cosmos-containers.json`](../infra/cosmos-containers.json), which Pulumi provisions. Details: [`packages/storage-cosmos`](../packages/storage-cosmos).

## PostgreSQL

Bring your own server: Azure Database for PostgreSQL (allow `VECTOR` in `azure.extensions`), Amazon RDS or Aurora, Google Cloud SQL, Supabase, Neon, or a container. It needs PostgreSQL 13 or later with the [pgvector](https://github.com/pgvector/pgvector) extension available.

| Setting | Env var | Default |
|---|---|---|
| `database.provider: "postgres"` | `DATABASE_PROVIDER=postgres` | |
| `database.connectionString` | `DATABASE_URL` | required, e.g. `postgres://user:pass@host:5432/agentforeach?sslmode=require` |
| `database.schema` | `DATABASE_SCHEMA` | `public` |
| `database.poolSize` | `DATABASE_POOL_SIZE` | `10` connections per instance |
| `database.serverTimeouts` | `DATABASE_SERVER_TIMEOUTS` | `true`: send a 30 s statement timeout and a 60 s idle-in-transaction timeout when connecting. `false` behind PgBouncer (see below) |
| | `DATABASE_PROVISION` | `false` on Azure Functions, `true` anywhere else (set it to `false` on other production hosts) |

### Local development

```bash
docker run -d --name agentforeach-pg -e POSTGRES_PASSWORD=pw -p 5432:5432 pgvector/pgvector:pg17
# gateway/local.settings.json:
#   "DATABASE_PROVIDER": "postgres",
#   "DATABASE_URL": "postgres://postgres:pw@localhost:5432/postgres"
```

Locally the runtime creates the extension, the tables and their indexes on first use.

### Production

Create the schema once with a role allowed to create extensions and tables, or have an administrator run `CREATE EXTENSION vector` first and use any role that can create tables in the schema. Then run the runtime with a role that only reads and writes rows:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f infra/postgres-schema.sql
```

[`infra/postgres-schema.sql`](../infra/postgres-schema.sql) is generated by `npm run db:catalog --workspace @agentforeach/gateway` from the same definitions as the Cosmos containers, and CI fails when it falls behind the code. Every statement is idempotent: re-apply it after an upgrade, before deploying the new version. With `DATABASE_PROVISION=false` (the default on Azure) the runtime never runs DDL. To provision on startup instead, set `DATABASE_PROVISION=true`. The role then needs `CREATE` on the database, and `CREATE EXTENSION vector` needs a role allowed to create it (a superuser, or `azure_pg_admin` on Azure).

On the Azure deployment, pass the settings through the Pulumi stack, which keeps secrets in Key Vault:

```bash
cd infra
pulumi config set --path 'extraAppSettings.DATABASE_PROVIDER' postgres
pulumi config set --secret --path 'extraAppSettings.DATABASE_URL' 'postgres://...?sslmode=require'
pulumi up
```

The stack still creates the Cosmos DB account, which a serverless account leaves idle at no cost, and it sets `COSMOS_PROVISION_CONTAINERS=false`, so the runtime expects the schema to be there: apply `infra/postgres-schema.sql` before the first deploy. Allow the Function App's outbound addresses through the database's firewall.

Size the pool for the number of instances: every Function App instance opens up to `DATABASE_POOL_SIZE` connections. With many instances, connect through a pooler in transaction mode (PgBouncer, or your provider's pooled connection string) and keep the pool small. PgBouncer refuses the timeout startup parameters, so set `DATABASE_SERVER_TIMEOUTS=false`. The adapter then still times out queries on the client side; the server-side timeouts are lost, as they are if you list them in PgBouncer's `ignore_startup_parameters` instead. The adapter's conformance suite was run through PgBouncer 1.26 in transaction mode and passed.

Each collection is one table, named like the collection (`"rate-limits"`): the document as `jsonb`, plus its partition key, id, etag, expiry, embedding and full-text columns. Expired rows are hidden at once and deleted by a background sweep. Details: [`packages/storage-postgres`](../packages/storage-postgres).

## Switching databases

The configuration switch is instant; the data does not move with it. A new deployment can start on either database. An existing one keeps its data in the database it started on; there is no migration tool yet.

## What differs

What the runtime can observe is the same on both. Underneath:

| | Cosmos DB | PostgreSQL |
|---|---|---|
| Vector search | diskANN above 505 dimensions (approximate), flat below | Exact cosine, with float32 vectors |
| Full-text ranking in hybrid search | BM25 | `ts_rank_cd` (term frequency and proximity, no inverse document frequency) |
| `count` | May include expired documents until Cosmos purges them | Exact |
| Object key order in returned documents | As written | Shorter keys first (jsonb). Array order is kept on both |
| Strings | Stores any JSON string | `\u0000` is refused (`BadRequest`), and a lone UTF-16 surrogate is stored as U+FFFD |
| Case-insensitive search (digests) | Cosmos `LOWER` | The database's `lower()`. Use a UTF-8 locale (the usual default). Under the plain `C` locale only ASCII letters fold |
| Cost when idle | Serverless: storage only | A running server, unless your provider scales to zero |
